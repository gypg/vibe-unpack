# vibe-unpack

**把普通人脑子里的模糊感觉，变成清晰、可执行、可验证的需求。**

vibe-unpack 是一个专为**完全非技术用户**设计的「需求解包器」。它通过结构化的追问，把「我想做一个像小红书但更简单的」「给手作店做一个网站」这类只有感觉、场景、情绪的模糊输入，一步步展开成带有硬约束、决策权衡、成功/失败定义的完整需求规格书 + 知识图。

**核心理念**：在写一行代码、推荐一个技术栈、匹配一个技能之前，先把需求真正搞清楚。

> **重要说明**：我们**故意没有在名字里加 "skill"**。  
> vibe-unpack **会被当作 Claude Code Skill 使用**（通过 `SKILL.md` 加载），但它的角色是**上游需求管理者（Manager）**，而不是执行层 skill。它绝不生成代码、内容、生产流程或术语润色。把 "unpack" 放在名字里，是为了突出它的唯一动作——把模糊拆解成可验证的需求。

**与其它同类工具的定位差异**（很重要）：
- **不是 khazix leader**：我们只做需求解包，不写可执行任务书、不分配子任务、不设计验收标准。
- **不是 vibe-hub**：我们不做术语提升、不做专业需求润色，我们只挖约束和决策。
- **不是任何执行层 skill**（rnskill、canghe 等）：我们绝不产生代码、脚本、内容生产流程。
- **我们的唯一产出**：冻结的需求规格（demand-spec.md + demand-graph） + 可视化（可选）。

如果你在用它的时候开始想“这个可以用 XX 实现”或“后面可以加功能”，说明你用错了位置——那不是 vibe-unpack 的工作。

### 为什么名字里没有 "skill"？

市面上很多开源的 Claude Code / Agent 技能仓库都叫 `xxx-skill` 或 `xxx-skills`（例如 khazix-skills、vibe-hub-skill、rnskill）。我们**刻意没有这么做**。

原因：
- 我们**不是执行型 skill**。执行型 skill 帮你写代码、剪视频、生成内容、跑流程。
- 我们是**上游需求管理者（Manager）**。我们的工作在任何技术决策、任何 skill 匹配、任何实现之前完成。
- 如果名字带 "skill"，很多人会默认以为我们会帮他"做东西"，从而产生错误的预期。
- 把名字定为 "vibe-unpack" 是为了清晰传达唯一动作：**把模糊的 vibe 彻底拆开**。

你仍然可以（也推荐）把它作为 Claude Code Skill 安装使用，只是请记住它的身份和边界。

## 它解决了什么？

普通人说需求时通常只有：
- 一种感觉（"我想记录孩子日常，但不要太复杂"）
- 一个场景（"给我的手作店做一个网站"）
- 一种情绪（"现在的工具都太烦人了"）

而真正的需求是：
- 硬约束（"我完全不会编程，3个月后可能就不管了"）
- 隐性假设（"我以为要像小红书一样，其实我只需要自己能快速翻到旧记录"）
- 权衡决策（"多人协作 vs 极简维护，我选极简"）
- 成功定义（"3个月后我还能自己维护，奶奶能自己看到内容"）

**vibe-unpack 就是把前者变成后者。**

### 它做了什么？（2026-07-31 更新后）

1. **把模糊变成可验证**  
   把“简单好用”“像小红书但更简单”这类无法证伪的表述，追问成具体的痛点时刻、硬约束、真实使用场景。

2. **显性化所有默认决策**  
   用户没回答的问题，只要我们必须往前推进的，都会写进「已确认的假设与默认决策」章节，执行者不得擅自修改。

3. **主动防范需求腐烂**  
   在对话过程中实时检测并记录空转语言、无法证伪的成功定义、隐性范围爆炸、维护能力谎报。

4. **输出极度克制，只给三样东西**  
   最终回复只允许：一句话用法引导 + 核心产物（demand-spec.md + demand-graph.json + 可选 Mermaid） + 一句话收尾。没有任何思考过程、追问历史、多个版本。

5. **输出必须同时服务人和 AI**  
   人类看可视化分支与剪枝图 + 结构化 Markdown；后续 Agent 直接消费 JSON + 规格书。

**最近一次重大升级**（2026-07-31，基于 khazix-skills leader、vibe-hub-skill、rnskill 等 7 个参考项目的系统分析）：

这次升级的核心目标是把 vibe-unpack 从一个"会问问题的工具"，变成一个**有强防御机制、输出合同极严的上游需求雕刻器**。

具体增强包括：
- **角色定位极度清晰**：明确自己是「需求管理者（Manager）」，不是执行者、不是技术顾问、不是术语润色工具，并与 khazix leader、vibe-hub、rnskill 等做了清晰切割。
- **法 vs 情报区分**：把必须 100% 遵守的铁律（法）和可灵活调整的建议（情报）明确分开。执行者看到"法"标记的内容时不得自行更改。
- **输出前自检清单**：在生成最终输出前，必须逐条确认 5 大类、30+ 条具体检查项（闭合性、空转语言、默认决策显性化、定位边界、输出格式）。任何一项不满足都必须先补问或补全。
- **主动实时防腐烂**：在整个对话过程中自动检测并记录空转语言、无法证伪的成功定义、隐性范围爆炸、维护能力谎报。
- **输出极度克制**：最终回复只允许三样东西，禁止任何思考过程、追问历史、多个版本。
- **显性化默认决策**：所有因为用户没回答但我们必须推进的内容，都写入专门章节。
- **提问纪律大幅收紧**：每轮只问 1 个问题，阶段有上限，空转语言必须当场拦截。
- **双格式输出**：人类看可视化分支剪枝图 + 结构化 Markdown；后续 Agent 直接把输出当作"冻结的真理"消费。

这些变化使得 vibe-unpack 的输出质量和可信度大幅提升，也极大降低了后续执行者被误导的风险。

## 核心铁律（永远不越界）

- ✅ 永远不推荐任何技术栈、框架、数据库
- ✅ 永远不匹配、推荐、筛选任何 skill
- ✅ 永远把「当前 workaround」作为唯一支点
- ✅ 痛点必须具体到「上周三晚上 10 点翻了 20 分钟」
- ✅ 输出必须同时服务**人类**（可视化图）和**AI**（结构化 JSON + Markdown）

| 场景 | 用户最初说的话 | 关键发现 | 推荐路径 |
|------|----------------|----------|----------|
| [C1 孩子日常](vibe-unpack/examples/c1-child-daily) | 像小红书但更简单，记录孩子日常 | 完全不会编程 + 奶奶只会微信 + 可能 3 个月不管 | 先手动整理 + 极简本地方案 |

| [C3 手作店](vibe-unpack/examples/c3-handmade-shop) | 给小手作店做一个清爽网站 | 每天被 5-10 个重复私信打扰才是最大痛 | 先做自动回复验证客服减负，再考虑 no-code |
| [C4 健身](vibe-unpack/examples/c4-fitness) | 记录健身 + 进度曲线激励自己 | 技术能力强但执行力低，复杂工具会更早放弃 | 先用备忘录验证 2 周，再做极简一行输入工具 |
| [C5 家庭相册](vibe-unpack/examples/c5-family-album) | 家庭相册共享，不想用微信 | 奶奶只会微信，技术能力完全不对称 | 混合方案：奶奶看精选推送 + 自己本地完整存档 |
| [C6 小说游戏](vibe-unpack/examples/c6-novel-game) | 把故事做成像原神一样的游戏 | 零编程 + 零美术 + 零预算 + 对复杂度严重低估 | 强制从纯文字 Twine 开始，永远不要从 Unity 开始 |

每个案例都包含完整的可读输出：
- `demand-spec.md` —— 人类可读的需求规格书
- `demand-graph.json` —— AI 可消费的结构化知识图
- `demand-graph.mmd` —— Mermaid 可视化分支与剪枝图
- `README.md` —— 案例解读

## 输出示例（C1 节选）

普通妈妈最初只说了一句话：

> 我想做一个像小红书但更简单的 App，专门记录我和孩子的日常。

经过引导后：

**致命约束**：
- 完全不会编程，身边也没有会技术的人 → 任何需要自己维护的方案都死
- 可能 3-6 个月后就不管了 → 必须能自己跑至少半年
- 奶奶只会用微信，技术能力极低 → 再酷的 App 对她也是零价值

**关键决策**：
- 多人协作 vs 极简个人 → 选极简（被「不会编程 + 奶奶不会用」直接剪掉）
- 云端 vs 本地 → 倾向本地（至少前 3 个月先验证）

**下一步行动**（具体可执行）：
1. 本周内把过去 3 个月的内容用固定格式整理一次
2. 找奶奶和老公直接看整理后的内容，观察他们能不能自主操作
3. 两周后自问：如果 3 个月我不管，这个东西还能不能自己用？

完整的可视化见 [examples/c1-child-daily/demand-graph.mmd](vibe-unpack/examples/c1-child-daily/demand-graph.mmd)。

## 安装与使用

### 作为 Claude Code Skill（推荐）

```bash
cp -r vibe-unpack ~/.claude/skills/vibe-unpack
```

之后在对话中遇到模糊需求时，Claude 会自动加载 `SKILL.md`。

**注意**：虽然我们把目录复制到了 `~/.claude/skills/` 下，但 **仓库名和 skill 名故意不带 "skill"**。这是刻意设计——它会被当作 skill 加载，但它的身份是上游需求管理者，而不是执行型 skill。

### 手动使用（任何支持 SKILL.md 的 Agent）

直接把 `vibe-unpack/SKILL.md` 的全部内容作为 system prompt 喂给模型，然后把用户的模糊描述扔进去即可。

### 自己扮演解包器

严格按照 `SKILL.md` 里的「铁律」「六大维度」「防范腐烂机制」和「输出前自检清单」去问自己或朋友，最后手动整理成 `demand-spec.md` + 图。
