# 演示范例：C2 - 极简记账

## 场景背景

用户想要一个记账工具，但**已经拒绝了所有市面上的复杂 App**，并且其实已经在用 Excel。

**关键发现**：用户最大的痛点其实不是“缺少工具”，而是“分类太细 + 月底手动对账”。

这个例子展示了 `vibe-unpack` 如何**挑战用户“要做一个 App”的默认假设**，并把用户引导到“先优化现有流程”的更现实路径上。

---

## 初始输入（极度模糊）

> 我想做一个记账的 App，就简单的，输入一下花了多少钱、干什么用的就行。不要像那些记账软件那么复杂，我用着烦。

---

## 核心展开结果

通过追问，挖出了以下致命信息：

- 用户**Excel 用得还可以**，但讨厌分类
- 主要用**信用卡**，账单本身已经有大部分数据
- 真实需求只是“月底快速知道吃饭花多少、孩子花多少”
- 历史上装过随手记等 App，几天就卸载

**决策点**：
1. 要不要做新 App？ → **强烈建议先不要**
2. 分类要不要精细？ → **必须大幅简化**

**推荐路径**：
先把 Excel 模板砍成 4-5 个粗分类，用 1 个月验证。如果还是痛苦，再考虑极简工具。

---

## 产出文件

- `demand-spec.md` — 给用户自己看的完整分析
- `demand-graph.json` — 结构化图谱
- `demand-graph.mmd` — 可视化（重点展示“做 App”这条路被剪掉的过程）

这个例子是“不要急着做产品，先验证现有流程是否真的不行”的经典示范。
