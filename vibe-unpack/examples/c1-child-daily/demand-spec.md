# 需求规格书：记录我和孩子的日常（照片、视频、小故事）

## 0. 执行摘要

用户想把孩子日常的照片、视频和简单故事保存下来，并能方便地分享给家里老人看。

**最核心的两个约束**：
- 用户完全不会编程，身边也没有任何会技术的人，**不可能自己维护复杂系统**。
- 用户时间极少（全职带娃），坚持意愿低，可能几个月后就放弃维护。

这意味着：任何需要持续维护、学习、配置的技术方案都几乎不可行。优先考虑极简、几乎零维护的方案。

---

## 1. 当前状态（Current Workaround）

**工具**：
- 手机备忘录（主要）
- 手机相册
- 微信（分享给家人）

**完整步骤**：
1. 日常用手机拍照或拍视频
2. 偶尔在备忘录里写一两句话记录当时情况
3. 想给奶奶看时，从备忘录或相册里找到内容，截图/截视频发微信
4. 想找以前的内容时，手动在备忘录里翻找（按时间倒序）

**每次耗时/心智负担**：
- 记录本身很快（拍照+写两句）
- 翻找历史记录很痛苦（上周三晚上翻了近20分钟还没找到3个月前的疫苗记录）
- 分享给奶奶需要额外操作（截图 + 单独发微信）

## 2. 痛点地图（Pain Map）

### 痛点 1：翻找历史记录极度困难
- **具体描述**（用户原话）：“上周三晚上10点，我突然想起来孩子3个月前打疫苗的日期和照片，结果备忘录里翻了快20分钟，还是没找到。”
- 频率：每月2-3次
- 严重程度：4/5
- 最近一次发生：上周三晚上10点
- 后果：奶奶一直问，用户只好说“忘了”，内心很烦

### 痛点 2：分享给家人需要重复劳动
- **具体描述**：想给奶奶看就得单独截图发微信，奶奶不会自己去翻备忘录。
- 频率：每周几次（奶奶想看的时候）
- 严重程度：3/5
- 问题根源：奶奶技术能力极低，无法自主查看

### 痛点 3：内容越来越乱，失去价值
- **具体描述**：备忘录里混杂了各种东西（购物清单、孩子记录、其他笔记），想找孩子相关的内容越来越难。
- 频率：持续恶化
- 严重程度：逐渐上升

## 3. 约束账本（Constraint Ledger）

### 能力与维护约束（最致命）
- **约束**：用户完全不会编程，身边认识的人里也没有任何会做 App / 网站 / 程序的人。
- **硬度**：Hard
- **证据来源**：用户明确回答“完全不会，我是全职妈妈，认识的人里也没有做技术的”
- **如果违反会怎样**：任何需要自己写代码、配置服务器、维护系统的方案都无法落地。用户根本没有能力启动。

- **约束**：用户时间极少，每天带孩子已经很累，只能“偶尔想起来弄一下”。
- **硬度**：Hard
- **如果违反会怎样**：需要频繁手动整理、分类、上传、配置的方案，用户大概率坚持不了两周就会放弃。

- **约束**：用户坚持意愿低，可能3-6个月后就完全不管这个东西。
- **硬度**：Hard
- **证据来源**：用户自己说“说不定过几个月我就不管了”
- **如果违反会怎样**：任何依赖“持续维护”“持续更新”“自己管理服务器”的方案，3个月后就会变成死数据或无法访问。

### 真实使用者能力约束
- **约束**：奶奶（重要查看者）年纪大，技术能力极低，只会用微信，不会用复杂App或网页。
- **硬度**：Hard
- **证据来源**：用户说“奶奶年纪大了，不会用太复杂的东西。现在发微信她还得我教。”
- **如果违反会怎样**：做出来没人能用，尤其是真正想给看的老人。

### 数据与持久性约束
- **约束**：不希望孩子相关记录丢失，至少希望能保留半年以上。
- **硬度**：Medium-Hard
- **证据来源**：用户说“我希望至少自己能用半年吧。数据最好别丢，因为以后孩子大了可能还想看。”
- **如果违反会怎样**：重要的成长记录永久消失，会后悔。

### 时间与预算约束
- **约束**：几乎没有额外预算。
- **约束**：几乎没有额外学习时间和精力。

## 4. 隐性假设与风险（Assumptions & Risks）

### 假设 1：“像小红书”意味着要做社区功能
- **实际风险**：用户其实并不需要陌生人点赞、关注、发现。她主要需求是**自己快速找到记录** + **简单分享给固定家人**。
- **风险等级**：Medium
- **后果**：如果按“社区”方向做，会引入大量不必要的复杂度（账号、权限、审核、推荐算法等），完全超出用户能力。

### 假设 2：“做个App”是最自然的解决方案
- **实际风险**：用户自己完全没有能力做App，也维护不了。做一个App反而可能是最差的路径。
- **风险等级**：High
- **后果**：浪费时间和精力，最后做不出来或做出来也用不起来。

### 假设 3：“数据一定要存在云端 / 服务器上”
- **实际风险**：用户对“数据不能丢”的容忍度其实是“至少半年能自己看到”，而不是“永远不丢、别人也永远能访问”。
- **风险等级**：Medium
- **后果**：引入云存储、账号、同步，反而增加了丢失风险（账号忘密码、平台倒闭、服务费停缴等）。

## 5. 成功与失败定义

### 成功样子（3-6个月后）
- 我还能比较轻松地找到3-6个月前的孩子记录（照片 + 简单说明），不需要翻很久。
- 奶奶能比较方便地看到我发给她的内容，不需要我每次都单独截图教她怎么看。
- 我每周至少用1-2次来记录，不觉得是额外负担。
- 数据没有莫名其妙丢失。

### 失败样子
- 我还是得手动翻备忘录找东西，找起来和以前一样痛苦。
- 做了之后我基本不用，因为操作比备忘录还麻烦。
- 三个月后我完全不管了，里面的东西也打不开了，或者全乱了。
- 奶奶还是只能靠我截图发微信。

## 6. 实现路径建议（高层级，绝不涉及具体技术）

**强烈建议的整体策略**：

**第一阶段（现在到未来3个月）：完全不写任何代码，先手动验证真正需求**

- 在现有工具上做一个极简的“手动增强版”，看看能不能坚持用。
- 目标是验证：**“我自己能不能持续记录 + 奶奶能不能比较方便地看到”** 这两件事。
- 建议动作：
  - 尝试在备忘录里建立一个固定的格式（例如每个记录都以日期+“孩子记录”开头）。
  - 或者尝试用一个独立的笔记本/文件夹，只放孩子相关的内容。
  - 每周固定找1-2次奶奶，让她直接看手机里的内容，观察她是不是真的能自己找到、看懂。
  - 记录自己用了几次、翻找了几次、奶奶看了几次、什么地方还是很烦。

**为什么必须先手动验证？**
- 用户自己坚持意愿很低。如果连手动记录都坚持不下来，任何App都救不了。
- 奶奶的真实使用门槛目前完全未知。很多“给老人用”的东西，做出来老人根本不会用。
- 目前最大的痛点可能是“内容太乱”和“分享需要重复操作”，而不是“没有一个App”。

**第二阶段（手动验证有效之后）**：
- 再考虑是否需要任何自动化/工具。
- 此时再评估：是继续优化现有手动流程，还是引入极简的工具。
- 核心评估标准：**“这个东西我3个月后不管了，它还能不能自己跑半年？”**

**强烈建议砍掉的范围（至少现在不要碰）**：
- 任何社交、点赞、评论、发现其他人的功能（用户不需要）
- 复杂的分类、标签、搜索系统（用户时间不够维护）
- 需要账号登录、云同步、多设备同步的方案（维护成本太高）
- 任何需要定期更新的后台、服务器、数据库

## 7. 关键决策记录

### 决策1：到底要不要“像小红书”？

**选项 A：做成类似小红书的社区/分享平台**
- 优点：内容可以被更多人看到、可能有反馈、感觉“正式”
- 缺点：需要账号、权限、公开/私密设置、审核、可能被陌生人看到、奶奶几乎不可能自己用
- 受约束影响：被“奶奶技术能力极低”“用户完全不会维护复杂系统”这两个硬约束直接剪掉

**选项 B：只给自己和固定家人用（极简记录 + 简单分享）**
- 优点：可以做到极简，奶奶有可能用，维护成本低
- 缺点：没有“被看到”的成就感
- 当前倾向：选 B
- 放弃代价：短期内可能觉得“不够酷”，但大幅降低失败概率

### 决策2：数据放在哪里？

**选项 A：完全本地（手机/电脑文件）**
- 优点：简单、不需要账号、隐私性好
- 缺点：换手机时可能麻烦、奶奶无法远程看
- 受约束影响：符合“不会维护复杂系统”

**选项 B：存在某个平台/云服务上**
- 优点：多设备可看、奶奶理论上能远程看
- 缺点：需要账号、可能收费、平台倒闭风险、用户不会管理
- 当前倾向：先倾向 A，至少前3个月先验证本地能不能解决主要痛点

### 决策3：谁是真正的主要用户？

**选项 A：主要给奶奶/家人看（以分享为核心）**
- 优点：解决了“奶奶一直问”的即时痛点
- 缺点：奶奶门槛极低的要求，会把方案限制得非常死

**选项 B：主要给自己记录和回顾（以自己能快速翻找为核心）**
- 优点：更符合用户自己翻记录的痛点
- 缺点：分享问题还是得另外解决
- 观察：用户其实两者都需要，但**奶奶能看**可能是更刚性的约束
