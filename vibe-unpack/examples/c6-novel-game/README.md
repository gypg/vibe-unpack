# 演示范例：C6 - 小说做成游戏（野心与能力完全不匹配）

## 场景背景

用户是文科生，有一个故事，想做成“像原神或文字冒险游戏”的东西。

**关键洞见**：用户有三个致命硬约束（不会编程、不会美术、零预算），但对游戏复杂度严重低估。

这个例子展示了 `vibe-unpack` 如何**用铁锤把用户的幻想打碎**，并把用户强制拉回现实。

---

## 初始输入

> 我脑子里有一个故事，想把它做成一个像《原神》或者文字冒险游戏的东西。就是玩家可以选择不同的路线，最后有不同结局。

---

## 展开后的残酷真相

通过追问发现：

- 用户是文科生，写过短篇
- **完全不会编程、不会画画、不会做音乐**
- **预算为零**
- 对“做游戏”的理解停留在“选分支 + 看结局”
- 真正驱动的是“想讲这个故事”，而不是“做游戏”

**被剪掉的路径**：
- 任何提到 Unity / Godot / C# 的方案
- 任何“自己画原画”“自己做 3D”的幻想
- 任何“上线 Steam”的目标
- 任何从“学编程”开始的路径

**决策点**：
1. 想讲故事 vs 想做游戏 → **必须讲故事优先**
2. 是否接受“不是游戏”的形式 → **必须接受**
3. 从哪个成本级别开始 → **必须从 Level 1（纯文字）开始**

**推荐路径**：
1. **今天**：写 500 字故事摘要
2. **今天**：回答问题 —— 如果只能用文字 + 10 张图片，还想讲吗？
3. **明天**：安装 Twine，做出 3-5 个节点的极简互动小说
4. **3 天内**：发给 2-3 个人读，收集反馈
5. **根据反馈**：决定是否值得投入更多资源

**被强制回答的问题**：
> 如果你只能用文字 + 最多 10 张我随便找的图片（或者 AI 生成的），你还想让别人读这个故事吗？为什么？

---

## 产出文件

- `demand-spec.md` — 完整分析（包含对用户的重锤）
- `demand-graph.json` — 知识图（展示所有技术路径如何被剪掉）
- `demand-graph.mmd` — 可视化

这个例子是“幻想 vs 现实”的极端案例，展示了 `vibe-unpack` 如何处理完全不切实际的野心。
