# 演示范例：C5 - 家庭相册共享（技术能力不对称）

## 场景背景

用户是 IT 从业者，想给全家（包括奶奶）做一个相册共享方案，不想用微信。

**关键洞见**：技术能力极度不对称 —— 用户自己可以自建 NAS + Immich，但**奶奶只会用微信**。

这个例子展示了 `vibe-unpack` 如何处理“统一平台”的幻想，并把用户引导到“混合方案”的现实路径。

---

## 初始输入

> 我想做一个家庭相册共享的东西。把家里人的照片、视频放到一个地方，大家都能看到和下载。不要用微信，因为微信空间有限，也不够整齐。

---

## 展开后的残酷真相

通过追问发现：

- 奶奶**只会用微信**，不会下载 App、不会注册账号、不会操作复杂界面
- 用户自己想“发一次就永久保存”，不想数据全在腾讯
- 用户在意隐私，奶奶完全不在意
- 用户希望“发一次就能永久保存”
- 视频发不出 + 翻历史困难

**决策点**：
1. 统一平台 vs 混合方案 → **必须混合**
2. 奶奶如何查看？ → **只能推送，不能让她主动打开新东西**

**推荐路径**：
- 奶奶只看“精选”（自动/半自动推送到微信或极简链接）
- 用户自己用本地 NAS / 外置硬盘 / iCloud 完整存档
- 接受“奶奶看不到全部”这个现实

**被剪掉的方案**：
- 纯自建 NAS + Immich/Nextcloud（奶奶不会用）
- 纯 Google Photos / iCloud（隐私顾虑）
- 要求全家人注册新 App 的方案

---

## 产出文件

- `demand-spec.md` — 完整分析（必须接受混合）
- `demand-graph.json` — 知识图（重点展示奶奶约束如何剪掉几乎所有方案）
- `demand-graph.mmd` — 可视化（奶奶技术能力为零是硬约束）

这个例子是“技术方案必须服务于最弱用户”的经典案例。
