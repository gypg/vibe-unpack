## 1. 项目定位（必须始终牢记）

vibe-unpack 是一个**上游需求解包器（Demand Unpacker / Manager）**，专门服务于**完全非技术用户**。

**唯一目标**：把普通人脑子里只有感觉、场景、情绪的模糊输入（“我想做一个像小红书但更简单的”），通过结构化追问，展开成**清晰、可验证、带硬约束**的需求规格书 + 知识图。

**铁律（永远不能打破）**：
- 绝不推荐任何技术、框架、数据库、部署方案
- 绝不匹配、推荐、筛选任何 skill
- 绝不产生代码、脚本、内容、生产流程
- 绝不假设用户“可以学”或“可以找人做”
- 输出必须同时服务**人类**（可视化 + 可读 Markdown）和**AI**（结构化 JSON）

**与其它工具的定位差异**（非常重要）：
- **不是 khazix leader**：我们只做需求解包，不写可执行任务书、不分配子任务、不设计验收标准。
- **不是 vibe-hub**：我们不做术语提升、不把口语改成专业术语，我们只挖约束和决策。
- **不是任何执行层 skill**（rnskill、canghe、huashu 等）：我们绝不生成内容或代码。
- **我们的唯一产出**：冻结的需求规格（`demand-spec.md` + `demand-graph.json`）+ 可选可视化。

名字里**故意没有加 "skill"**，就是为了避免用户误以为它会帮他“做东西”。

## 2. 已完成的核心工作（截至 2026-07-31）

### 2.1 核心规则大幅强化（Tier 1 全部落地）

基于对 khazix-skills（leader）、vibe-hub-skill、rnskill 等 7 个参考项目的深入分析，对 `vibe-unpack/SKILL.md` 进行了系统性升级：

- 明确角色是「需求管理者（Manager）」，不是执行者
- 引入「法 vs 情报」区分（铁律必须 100% 遵守，建议可以灵活调整）
- 新增「输出前自检清单」（闭合性、空转语言、默认决策显性化、定位边界、输出格式 五大类 30+ 条检查）
- 主动实时防范需求腐烂（空转语言、无法证伪的成功定义、隐性范围爆炸、维护谎报）
- 输出极度克制：最终回复只允许三样东西
- 显性化所有「已确认的假设与默认决策」
- 提问纪律大幅收紧（每轮只问 1 个问题、阶段上限、空转语言当场拦截）

**关键文件**：`vibe-unpack/SKILL.md`（407 行，当前权威规则）

### 2.2 6 个真实压力场景示例全部更新为新模板

所有示例现在都符合当前 SKILL.md 定义的模板：

- 包含标准头部 `> **给执行者的重要提示**`
- 包含第 6 节「已确认的假设与默认决策（执行者必须遵守）」
- 章节统一为 0-9（共 10 节）

**示例目录**：`vibe-unpack/examples/c1-child-daily` ~ `c6-novel-game`

每个示例包含：
- `demand-spec.md`（人类可读）
- `demand-graph.json`（AI 可消费）
- `demand-graph.mmd`（Mermaid 可视化）
- `README.md`（案例解读）

### 2.3 文档与定位说明更新

- 根 `README.md` 和 `vibe-unpack/README.md` 都详细说明了“为什么名字里没有 skill”以及本次强化的具体内容
- 新增了「它做了什么？（2026-07-31 更新后）」和「最近一次重大升级」章节
- 安装说明中反复强调身份与边界

## 4. 后续可能的开发方向

以下内容主要来自 `docs/optimization/optimization-proposal.md` 和 `vibe-unpack/README.md`，按优先级/投入排序：

### Tier 2（建议优先考虑，投入中等）

1. **进一步完善「给后续执行者的快速指引」**（Next Agent Quick Guide）
   - 在 `demand-spec.md` 顶部或单独文件，提供更简洁的“执行者必须先读这几段”的指引。
   - 当前已有头部提示，可再精炼或独立成小文件。

2. **在 README 中继续深化定位差异**
   - 虽然已经写了不少，但可以更简洁有力地说明“我们和 khazix leader / vibe-hub 的本质区别”。

3. **把示例作为“规则冻结后的第一批合规输出”进行小幅复盘**
   - 收集使用这些新模板的真实感受（如果有），反哺规则微调。

### Tier 3（长期 / 工具化方向，投入较高）

- 自动化生成 Mermaid / HTML 可视化
- 需求腐烂检查器（可作为独立小工具或在解包过程中实时提示）
- 更多领域案例（目前只有 6 个，覆盖面仍有限）
- 与执行型 skill 的接力流程文档（例如“vibe-unpack 完成后，接下来推荐用哪个 skill 执行”）
- 可选的独立「技能匹配」skill（**明确不放在本项目**）

### 不建议做的事情（保护定位）

- 不要让 vibe-unpack 开始推荐具体技术方案
- 不要让它生成代码、内容、生产流程
- 不要把它做成“万能需求工具”，它应该保持极度上游、极度克制的定位
- 不要过早追求漂亮的可视化工具（核心规则质量更重要）

## 6. 如何本地快速验证

```bash
# 手动验证示例是否符合当前模板
python3 - << 'EOF'
import re, glob
for path in sorted(glob.glob("vibe-unpack/examples/*/demand-spec.md")):
    name = path.split("/")[-2]
    with open(path, encoding="utf-8") as f: c = f.read()
    ok = ("> **给执行者的重要提示**" in c and
          "## 6. 已确认的假设与默认决策（执行者必须遵守）" in c and
          re.findall(r"^## (\d+)\.", c, re.M) == [str(i) for i in range(10)])
    print(name, "PASS" if ok else "FAIL")
EOF
```
